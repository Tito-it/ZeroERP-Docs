listini_righe_componenti¶

Vedi anche

  • vendite.listini_versioni — versione listino di riferimento
  • catalogo.articoli_componenti — riga BoM di riferimento
  • catalogo.articoli — padre e figlio (denorm)
  • vendite.listini_righe — prezzi standalone (non compositi)
  • script.trgfn_listini_righe_comp_guard_coerenza_bom — guard 7 invarianti BoM
  • vendite.trgfn_listini_righe_comp_guard_immutabilita_v5 — guard immutabilità versione attiva
  • vendite.fn_resolve_prezzo_listino_v2 — resolver che consulta questa tabella

Scopo¶

Contiene i prezzi bundle per i componenti BoM in un contesto di versione listino specifico. Una riga rappresenta il prezzo del componente X dell'articolo padre composito Y nella versione listino V. Permette di negoziare un prezzo diverso per un componente quando viene venduto come parte di un composito, senza toccare il prezzo standalone del componente stesso. Il prezzo padre composito è sempre la somma dei prezzi dei suoi componenti: non esiste una riga in listini_righe per il padre (bloccato da guard dedicati).

Schema DB¶

vendite

DDL principale¶

CREATE TABLE vendite.listini_righe_componenti (
    id                      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    listino_versione_id     BIGINT        NOT NULL
                            REFERENCES vendite.listini_versioni(id),
    articolo_componente_id  UUID          NOT NULL
                            REFERENCES catalogo.articoli_componenti(id),
    articolo_padre_id       UUID          NOT NULL
                            REFERENCES catalogo.articoli(id),
    articolo_figlio_id      UUID          NOT NULL
                            REFERENCES catalogo.articoli(id),
    prezzo                  NUMERIC(18,6) NOT NULL,
    iva_id                  BIGINT        REFERENCES config.iva(id),
    validita                DATERANGE     NOT NULL,
    attivo                  BOOLEAN       NOT NULL DEFAULT TRUE,
    meta                    JSONB         NOT NULL DEFAULT '{}'::jsonb,
    tx_id                   UUID,
    user_insert             TEXT,
    data_insert             TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    user_update             TEXT,
    data_update             TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    CONSTRAINT chk_listrighe_comp_prezzo_notnull
        CHECK (prezzo IS NOT NULL)
);

Colonne principali¶

Colonna Tipo Descrizione
id BIGINT IDENTITY PK tecnica
listino_versione_id BIGINT FK Versione listino di appartenenza
articolo_componente_id UUID FK Riga BoM (catalogo.articoli_componenti) — chiave semantica
articolo_padre_id UUID FK Articolo padre composito — denorm di articoli_componenti.prodotto_id
articolo_figlio_id UUID FK Articolo componente — denorm di articoli_componenti.componente_id
prezzo NUMERIC(18,6) Prezzo bundle del componente in questo contesto listino
iva_id BIGINT FK Aliquota IVA (deve coincidere con quella del padre/figlio per invariante BoM)
validita DATERANGE Periodo di validità del prezzo bundle
attivo BOOLEAN Flag soft-delete — usare attivo = FALSE invece di DELETE
meta JSONB Metadati liberi

Colonne audit: user_insert, data_insert, user_update, data_update, tx_id.

Indici¶

Indice Tipo Descrizione
ex_listini_righe_comp_no_overlap GiST (listino_versione_id, articolo_componente_id, validita) WHERE attivo = TRUE — esclude overlap di periodo per la stessa coppia versione/componente
ix_listini_righe_comp_padre_data B-tree (articolo_padre_id, listino_versione_id) WHERE attivo = TRUE — ottimizza la ricerca bundle-aware nel resolver
Indici FK B-tree Gestiti da dbops.apply_fk_index_policy() in 90_end

Trigger¶

Trigger Fase Evento Funzione
trg_listrighe_comp_a10_guard_coerenza_bom_ins_upd _a10_ BEFORE INSERT OR UPDATE script.trgfn_listini_righe_comp_guard_coerenza_bom
trg_listrighe_comp_a10_guard_immutabilita_v5_ins_upd_dlt _a10_ BEFORE INSERT OR UPDATE OR DELETE vendite.trgfn_listini_righe_comp_guard_immutabilita_v5
trg_listrighe_comp_audit_data_user_ins_upd — BEFORE INSERT OR UPDATE script.trgfn_audit_data_user_generic
trg_listrighe_comp_gen_tx_id_ins_upd — BEFORE INSERT OR UPDATE dbops.trgfn_tx_id_managed

Come si usa¶

Il resolver fn_resolve_prezzo_listino_v2 consulta questa tabella quando riceve il parametro p_articolo_padre_contesto != NULL. Se trova una riga attiva e valida alla data richiesta, restituisce il prezzo con origine = 'LISTINO_BUNDLE'. In assenza di riga bundle, il resolver può fare fallback al prezzo standalone del componente in listini_righe.

Differenza da listini_righe¶

listini_righe listini_righe_componenti
Articolo Qualsiasi articolo non-composito Solo componenti di articoli compositi
Prezzo Prezzo standalone dell'articolo Prezzo bundle quando venduto come parte del padre
Resolver Query base senza contesto padre Query con p_articolo_padre_contesto valorizzato
Origine LISTINO_STANDALONE LISTINO_BUNDLE

Perché articolo_padre_id e articolo_figlio_id come denorm¶

Le colonne articolo_padre_id e articolo_figlio_id duplicano informazioni già presenti in catalogo.articoli_componenti. La denormalizzazione è intenzionale: velocizza il resolver fn_resolve_prezzo_listino_v2 eliminando una JOIN extra su articoli_componenti in ogni lookup prezzo. La coerenza delle colonne denorm è garantita a livello DB dal trigger trgfn_listini_righe_comp_guard_coerenza_bom (guard 2 e 3).

Dipendenze¶

Oggetto Tipo Motivo
vendite.listini_versioni Tabella Versione listino di appartenenza
catalogo.articoli_componenti Tabella Riga BoM di riferimento
catalogo.articoli Tabella Padre e figlio (chiavi FK denorm)

Note operative¶

  • DELETE è sempre bloccato dal trigger di immutabilità: usare attivo = FALSE.
  • INSERT è consentito solo su versioni in stato BOZZA.
  • UPDATE di prezzo, iva_id, validita è bloccato se la versione è in stato diverso da BOZZA.
  • Migration di riferimento: 20260513-18.
