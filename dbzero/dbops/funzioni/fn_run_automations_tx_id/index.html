    🎯 Scopo Principale¶

    (latest review 26-12-25) La funzione dbops.fn_run_automations_tx_id(p_exec_mode, p_schemas, p_dry_run) automatizza la creazione (o la simulazione) del trigger di gestione tx_id (BEFORE INSERT OR UPDATE) sulle tabelle applicative che possiedono una colonna tx_id uuid. Il trigger invoca dbops.trgfn_tx_id_managed() per generare/propagare l’ID di transazione.

    🔍 Parametri di input¶

    Parametro Tipo Obbligatorio Descrizione
    p_exec_mode text ✔️ Modalità di esecuzione (AUTO, FORCE, CHECK).
    p_schemas text[] ❌ Scope di schemi. Se NULL, determinato da fn_resolve_scope.
    p_dry_run boolean ✔️ Se true, non crea trigger ma registra un evento DRYRUN in audit_log.

    📤 Valore di ritorno¶

    void – non restituisce valori; crea i trigger necessari o produce log di simulazione.

    ⚙️ Flusso logico¶

    1. Scope: calcola gli schemi effettivi con fn_resolve_scope (se p_schemas è NULL).
    2. Scansione tabelle: itera tutte le tabelle “user” in scope (fn_table_in_scope).
    3. Selezione regole: per ciascuna tabella, filtra le regole abilitate in automation_rules_tbl con rule_type='TX_ID', rispettando exec_mode, priorità e target (schema/tabella).
    4. Presenza colonna: verifica che esista la colonna tx_id uuid.
    5. Naming trigger: risolve il nome con fn_name_from_template (default trg_{table}_ins_upd_gen_tx_id).

    6. Strategia esistenza:

    7. BY_NAME: usa fn_trigger_exists_by_name.

    8. BY_FUNCTION: usa fn_trigger_exists_by_function(...,'dbops','trgfn_tx_id_managed').
    9. BOTH: richiede che almeno uno dei due controlli sia vero.

    10. Azione:

    11. p_dry_run=true → registra evento DRYRUN_CREATE_TRIGGER via fn_audit_log_once (con dettagli di tabella e trigger).

    12. p_dry_run=false → crea il trigger BEFORE INSERT OR UPDATE ... EXECUTE FUNCTION dbops.trgfn_tx_id_managed() con EXECUTE format.
    13. Error handling: intercetta eccezioni ed invoca script.fn_log_and_raise_error('E_TX_ID', ...) con contesto.

    🧩 Casi d’uso tipici¶

    • Allineamento post‑deploy: garantire che tutte le tabelle con tx_id abbiano il trigger di gestione coerente.
    • Refactoring: dopo l’introduzione della colonna tx_id in nuove tabelle, applicare automaticamente la policy.
    • Simulazione: in dry_run validare l’impatto senza eseguire DDL.

    🛡️ Permessi e sicurezza¶

    • Richiede privilegi DDL per creare trigger.
    • In dry_run non modifica oggetti (utile per pipeline CI o analisi su ambienti restrittivi).

    🚀 Esempi di utilizzo¶

    • Simulazione: SELECT dbops.fn_run_automations_tx_id('AUTO', ARRAY['anagrafiche'], true);
    • Applicazione reale: SELECT dbops.fn_run_automations_tx_id('FORCE', NULL, false);

    📌 Considerazioni¶

    • Il controllo di esistenza è flessibile grazie a existence_strategy (compatibile con ambienti legati a naming legacy).
    • Il template del nome trigger può essere personalizzato via name_template in automation_rules_tbl.
    • Si integra con il framework di audit (fn_audit_log_once) per tracciare simulazioni e azioni reali.

    ✅ Benefici¶

    • Coerenza: applica in modo uniforme la gestione di tx_id su tutto lo scope.
    • Automazione: riduce al minimo gli interventi manuali.
    • Flessibilità: supporta nomi e strategie di esistenza personalizzabili.

    🧠 In sintesi: fn_run_automations_tx_id è il modulo che garantisce la presenza e la corretta gestione del tx_id in tutte le tabelle interessate, con supporto a simulazione, naming template e strategie di idempotenza.

    ⚙️ Funzione fn_run_automations_tx_id¶

    CREATE FUNCTION fn_run_automations_tx_id(p_exec_mode text, p_schemas text[], p_dry_run boolean)

    Definizione completa:

    CREATE OR REPLACE FUNCTION dbops.fn_run_automations_tx_id(p_exec_mode text, p_schemas text[], p_dry_run boolean)
 RETURNS void
 LANGUAGE plpgsql
AS $function$
DECLARE
  v_schemas text[];
  rtab record;
  rrule record;
  rel  regclass;
  has_txid boolean;
  tmpl     text;
  trg_name text;
  exist_strat text;
BEGIN


/*
  Scopo
  -----
  Esegue l'automazione di provisioning dei trigger "TX_ID managed" sulle tabelle in scope,
  applicando le regole abilitate in dbops.automation_rules_tbl di tipo 'TX_ID'.

  La funzione:
  1) risolve lo scope degli schemi (dbops.fn_resolve_scope),
  2) scorre tutte le tabelle fisiche (pg_class.relkind='r') degli schemi target
    filtrate da dbops.fn_table_in_scope(schema, table),
  3) per ogni tabella applica le regole TX_ID compatibili con:
    - enabled = true
    - rule_type = 'TX_ID'
    - exec_mode = 'AUTO' oppure exec_mode = p_exec_mode
    - match su schema (dbops.fn_schema_match)
    - match su tabella: '*ALL' oppure pattern ILIKE su r.target_table
  4) verifica la pre-condizione tecnica: la tabella deve avere una colonna tx_id di tipo uuid
    (information_schema.columns).
    Se la colonna non esiste, la tabella viene ignorata (non crea colonne, crea solo trigger).

  Trigger generato
  ----------------
  Per le tabelle idonee, la funzione assicura l'esistenza del trigger:
    BEFORE INSERT OR UPDATE
    EXECUTE FUNCTION dbops.trgfn_tx_id_managed()
  Il nome del trigger è derivato da un template:
    - rrule.name_template (default: 'trg_{table}_gen_tx_id_ins_upd')
    - dbops.fn_name_from_template per generare un nome coerente e standardizzato.

  Esistenza trigger / strategie
  -----------------------------
  La creazione del trigger è condizionata da rrule.existence_strategy (default 'BY_NAME'):
  - BY_NAME     : verifica esistenza per nome trigger
  - BY_FUNCTION : verifica esistenza per funzione trigger (dbops.trgfn_tx_id_managed)
  - BOTH        : considera presente se esiste per nome OR per funzione
  Questo consente migrazioni controllate e previene duplicazioni.

  Modalità DRY RUN
  ---------------
  Se p_dry_run=true non esegue DDL (CREATE TRIGGER) e registra invece un audit
  con dbops.fn_audit_log_once indicando cosa verrebbe creato.

  Error handling
  --------------
  In caso di errore nella creazione del trigger, log strutturato e rilancio tramite
  script.fn_log_and_raise_error includendo tabella, contesto ('TX_ID') e SQLERRM.
*/


  v_schemas := dbops.fn_resolve_scope(p_schemas); 
  FOR rtab IN
    SELECT n.nspname AS schema_name,
          c.relname AS table_name,
          (quote_ident(n.nspname)||'.'||quote_ident(c.relname))::regclass AS rel
    FROM pg_class c
    JOIN pg_namespace n ON n.oid=c.relnamespace
    WHERE c.relkind='r'
      AND n.nspname = ANY(v_schemas)
      AND dbops.fn_table_in_scope(n.nspname, c.relname)
  LOOP
    rel := rtab.rel;

    FOR rrule IN
      SELECT *
        FROM dbops.automation_rules_tbl r
      WHERE r.enabled
        AND upper(btrim(r.rule_type))='TX_ID'
        AND dbops.fn_schema_match(r.target_schema, rtab.schema_name)
        AND (UPPER(r.target_table) = '*ALL' OR rtab.table_name ILIKE r.target_table)
        --AND (r.exec_mode='AUTO' OR r.exec_mode=p_exec_mode)
        AND (upper(btrim(r.exec_mode)) = 'AUTO' OR r.exec_mode = p_exec_mode)
      ORDER BY r.priority, r.id
    LOOP
      exist_strat := COALESCE(rrule.existence_strategy,'BY_NAME');

      SELECT EXISTS(
        SELECT 1 FROM information_schema.columns
        WHERE table_schema=rtab.schema_name
          AND table_name =rtab.table_name
          AND column_name='tx_id' AND udt_name='uuid'
      ) INTO has_txid;

      IF has_txid THEN
        tmpl     := COALESCE(rrule.name_template,'trg_{table}_gen_tx_id_ins_upd');
        trg_name := dbops.fn_name_from_template(tmpl, rtab.schema_name, rtab.table_name, NULL,NULL,NULL,NULL);

        IF (exist_strat='BY_NAME'     AND NOT dbops.fn_trigger_exists_by_name(rel, trg_name))
        OR (exist_strat='BY_FUNCTION' AND NOT dbops.fn_trigger_exists_by_function(rel,'dbops','trgfn_tx_id_managed'))
        OR (exist_strat='BOTH'        AND NOT (dbops.fn_trigger_exists_by_name(rel, trg_name)
                                          OR dbops.fn_trigger_exists_by_function(rel,'dbops','trgfn_tx_id_managed')))
        THEN
          IF p_dry_run THEN

            PERFORM dbops.fn_audit_log_once(
                  p_function_name => 'dbops.fn_run_automations',
                  p_status        => 'DRYRUN',
                  p_rule_type     => 'E_TX_ID',
                  p_exec_mode     => p_exec_mode,
                  p_parts         => ARRAY['TX_ID'],
                  p_dry_run       => true,
                  p_params        => jsonb_build_object(
                                      'table', rtab.schema_name||'.'||rtab.table_name,
                                      'trigger', trg_name,
                                      'action', 'DRYRUN_CREATE_TRIGGER'   
                                    ),
                  p_message       => 'Trigger would be created'
                );

          ELSE
            BEGIN
              EXECUTE format($f$
                CREATE TRIGGER %I
                BEFORE INSERT OR UPDATE ON %I.%I
                FOR EACH ROW
                EXECUTE FUNCTION dbops.trgfn_tx_id_managed()
              $f$, trg_name, rtab.schema_name, rtab.table_name);
            EXCEPTION WHEN others THEN
                PERFORM script.fn_log_and_raise_error(
                  'dbops',
                  'run_automations',
                  'E_TX_ID',
                  jsonb_build_object(
                    'where','TX_ID',
                    'table', rtab.schema_name||'.'||rtab.table_name,
                    'error', SQLERRM
                  ) , NULL::uuid, SQLERRM
                );

            END;
          END IF;
        END IF;
      END IF;
    END LOOP;
  END LOOP;
END;
$function$
