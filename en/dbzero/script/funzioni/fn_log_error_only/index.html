    📘 Documentazione Concettuale – Funzione script.fn_log_error_only¶

    👀 Vedi anche

    • script.fn_log_and_raise_error (log + abort)

    La funzione script.fn_log_error_only registra solo un messaggio in dbops.error_log senza interrompere l’esecuzione. È ideale per:

    • Tracciare attività, eventi o warning che non devono bloccare il flusso applicativo.
    • Loggare informazioni diagnostiche o transazionali di routine.

    🎯 Scopo Principale¶

    • Logging “silenzioso”: inserisce una riga in dbops.error_log con contesto ricco, ma non solleva eccezioni.
    • Separazione delle responsabilità: differenzia chiaramente i casi di solo tracciamento da quelli di error handling critico (per cui usare fn_log_and_raise_error).

    🔍 Parametri di Input¶

    Nome Tipo Descrizione
    p_area TEXT Area di applicazione (es. 'database', 'service', ecc.)
    p_function_name TEXT Nome della funzione o del contesto chiamante
    p_error_code TEXT Codice di riferimento del messaggio in config.messaggi_errore (es. 'E_STORICO_MANCANTE')
    p_context JSONB Oggetto JSON con informazioni di contesto (es. tabella, record, parametri)
    p_tx_id UUID ID della transazione corrente (se NULL, viene generato automaticamente)
    VARIADIC p_valori TEXT[] Valori da sostituire nei placeholder del messaggio (uso format)

    ⚙️ Flusso di Esecuzione¶

    1. Recupero tx_id: se p_tx_id è NULL, invoca dbops.fn_get_or_create_session_tx_id().

    2. Lookup del messaggio: cerca in config.messaggi_errore il record corrispondente a p_error_code e lingua (GUC myapp.user_language).

    3. Se non trovato, usa il codice 'MESSAGGIO_NON_DEFINITO'.

    4. Sostituzione placeholder: applica format(v_msg, VARIADIC p_valori) se presenti.
    5. Insert su dbops.error_log: costruisce dinamicamente l’INSERT con dblink_exec in connessione separata.
    6. Fine: termina senza sollevare nulla, proseguendo il normale flusso PL/pgSQL.

    💡 Vantaggi Operativi¶

    • Non blocca: permette di tracciare eventi non critici senza interrompere transazioni o logica applicativa.
    • Contesto ricco: i campi messaggio_errore_id, context e tx_id garantiscono alta tracciabilità.
    • Riutilizzabile: può essere usata in trigger, stored procedure o funzioni PL/pgSQL per attività di auditing o monitoraggio.
    • Chiarezza: distingue in modo esplicito il “solo logging” dal “log + abort” (fn_log_and_raise_error).

    🧠 “Usa fn_log_error_only per il logging passivo—per casi in cui vuoi solo registrare, mai bloccare.”

    ⚙️ Funzione fn_log_error_only¶

    CREATE FUNCTION fn_log_error_only(p_area text, p_function_name text, p_error_code text, p_context jsonb, p_tx_id uuid, VARIADIC p_valori text[])

    Definizione completa:

    CREATE OR REPLACE FUNCTION script.fn_log_error_only(p_area text, p_function_name text, p_error_code text, p_context jsonb, p_tx_id uuid, VARIADIC p_valori text[])
 RETURNS void
 LANGUAGE plpgsql
AS $function$
  DECLARE
      v_id     BIGINT;
      v_msg    TEXT;
      v_detail TEXT;
      v_hint   TEXT;
      v_lang   TEXT := coalesce(current_setting('myapp.user_language', TRUE), 'it');
      v_ctx    JSONB := p_context;
      v_sql    TEXT;
  BEGIN
      -- -------------------------------------------------
      -- Input
      -- p_area: area di applicazione (esempio: 'database')
      -- p_function_name: nome della funzione chiamante
      -- p_error_code: codice dell'errore da loggare
      -- p_context: contesto dell'errore (JSONB)
      -- p_tx_id: ID della transazione corrente (se NULL, viene generato automaticamente)
      -- p_valori: valori variabili da inserire nel messaggio di errore
      -- Output
      -- Logga l'errore nel database senza sollevare eccezione
      -- -------------------------------------------------
      -- opzionale: spegni logging via dblink in certe sessioni (es. CI)
      IF coalesce(current_setting('myapp.log_with_dblink', true), 'on') <> 'on' THEN
        RETURN;
      END IF;

      IF p_tx_id IS NULL THEN
          p_tx_id := dbops.fn_get_or_create_session_tx_id();
      END IF;

      SELECT id, messaggio, causa, soluzione
        INTO v_id, v_msg, v_detail, v_hint
        FROM config.messaggi_errore
      WHERE codice = p_error_code AND lingua = v_lang;

      IF NOT FOUND THEN
        SELECT messaggio||' '||p_error_code, causa, soluzione
          INTO v_msg, v_detail, v_hint
          FROM config.messaggi_errore
          WHERE codice='MESSAGGIO_NON_DEFINITO' AND lingua=v_lang;
        IF v_msg IS NULL THEN
            v_msg := '[MESSAGGIO NON DEFINITO: '||p_error_code||']';
            v_detail := 'Catalogo mancante='||quote_literal(p_error_code);
            v_hint   := 'Aggiungere record in config.messaggi_errore';
            v_id     := NULL;
        END IF;
      END IF;

      IF array_length(p_valori,1) IS NOT NULL THEN
          v_msg := format(v_msg, VARIADIC p_valori);
      END IF;

      v_sql := format(
        'INSERT INTO dbops.error_log(occurred_at, area, function_name, messaggio_errore_id, context, tx_id)
        VALUES (now(), %L, %L, %s, %L::jsonb, %L::uuid)',
        p_area, p_function_name, coalesce(v_id::text,'NULL'), v_ctx::text, p_tx_id::text
      );
      PERFORM dblink_exec('logconn'::text, v_sql, true);
  END;
  $function$
