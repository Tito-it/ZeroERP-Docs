    📘 Documentazione Concettuale – Funzione script.fn_get_indirizzo¶

    👀 Vedi anche

    Approfondimento tabelle:

    • anagrafiche.indirizzi
    • anagrafiche.indirizzi_dettaglio
    • anagrafiche.soggetti_ruoli
    • config.tipi_indirizzi
    • config.tipi_ruolo_tipi_indirizzo
    • config.comuni
    • config.codici_postali

    Approfondimento funzioni:

    • script.fn_get_indirizzi_by_ruolo

    🎯 Scopo Principale¶

    (latest review 01-12-25) La funzione script.fn_get_indirizzo restituisce uno o più indirizzi tecnici associati a un determinato soggetto_ruolo, filtrando per tipo di indirizzo identificato dal codice interno (config.tipi_indirizzi.codice_interno).

    La funzione:

    • non implementa la logica di composizione dell’indirizzo,
    • delega integralmente il recupero e la normalizzazione dei dati a script.fn_get_indirizzi_by_ruolo,
    • aggiunge una logica di fallback multi-livello basata sulla matrice di configurazione config.tipi_ruolo_tipi_indirizzo.

    In pratica:

    “Dammi l’indirizzo per questo tipo; se non esiste, segui la catena di fallback definita in config.tipi_ruolo_tipi_indirizzo finché trovi uno o più indirizzi utilizzabili, o finché la catena termina.”

    📌 Nota di ambito La funzione opera esclusivamente a livello di soggetto_ruolo e utilizza la matrice ruolo ↔ tipo indirizzo. Non coinvolge né consulta la matrice config.tipi_soggetto_dettaglio_tipi_indirizzo, che è invece riferita agli indirizzi diretti del soggetto.

    🧩 Firma (reale)¶

    CREATE OR REPLACE FUNCTION script.fn_get_indirizzo(
  p_soggetto_ruolo_id bigint,
  p_tipo_codice       character varying
)
RETURNS TABLE(
  tipo_indirizzo          character varying,
  indirizzo_completo     text,
  geoloc                 geometry,
  indirizzo_id           bigint,
  soggetto_ruolo_id      bigint,
  tipo_indirizzo_id      integer,
  indirizzo_dettaglio_id bigint,
  indirizzo_libero       text,
  is_normalizzato        boolean,
  stato_id               integer,
  stato_descrizione      character varying,
  stato_iso2             character,
  regione_id             integer,
  regione_descrizione    character varying,
  provincia_id           integer,
  provincia_sigla        character varying,
  provincia_descrizione  character varying,
  comune_id              integer,
  comune_descrizione     character varying,
  codice_postale_id      integer,
  cap_codice             character,
  locality               character varying,
  administrative_area    character varying,
  sublocality            character varying,
  postal_box             character varying
)
LANGUAGE plpgsql
STABLE
PARALLEL UNSAFE;

    📌 Il result-set restituito è identico a quello prodotto da script.fn_get_indirizzi_by_ruolo, con la sola differenza che i record sono filtrati per tipo indirizzo e fallback.

    🔢 Parametri di input¶

    Nome Tipo Descrizione
    p_soggetto_ruolo_id bigint ID della relazione in anagrafiche.soggetti_ruoli.
    p_tipo_codice varchar Codice interno del tipo indirizzo (config.tipi_indirizzi.codice_interno, es. RES, FATT, SEDEOP).

    🔹 Il tipo indirizzo viene passato tramite codice interno (chiave funzionale stabile), non tramite ID tecnico.

    📤 Valori restituiti¶

    La funzione restituisce zero, uno o più record, tutti con struttura completa e coerente, derivata direttamente da fn_get_indirizzi_by_ruolo.

    Alcuni campi rilevanti:

    Colonna Tipo Descrizione
    tipo_indirizzo varchar Codice interno del tipo indirizzo effettivamente utilizzato (post-fallback).
    indirizzo_completo text Indirizzo formattato in forma human-readable.
    geoloc geometry Geolocalizzazione (SRID 4326), se disponibile.
    is_normalizzato boolean TRUE se derivato da indirizzi_dettaglio, FALSE se indirizzo libero/estero.
    indirizzo_id bigint Identificativo tecnico dell’indirizzo.
    tipo_indirizzo_id integer ID tecnico del tipo indirizzo effettivo.

    📌 Tutti gli altri campi geografici (stato, regione, provincia, comune, CAP) sono già risolti e coerenti, in quanto prodotti dalla funzione base.

    🧠 Logica di funzionamento (concettuale)¶

    La funzione implementa una ricerca iterativa con fallback configurabile:

    1. Determina il tipo ruolo associato al soggetto_ruolo.
    2. Prova a recuperare indirizzi del tipo richiesto (p_tipo_codice).
    3. Se vengono trovati uno o più record, li restituisce e termina.

    4. In assenza di risultati:

    5. consulta config.tipi_ruolo_tipi_indirizzo per individuare un fallback_tipo_indirizzo_id,

    6. traduce l’ID in codice_interno,
    7. ripete il tentativo.

    8. La catena termina quando:

    9. viene trovato almeno un indirizzo,

    10. il fallback è NULL,
    11. viene rilevato un loop nella catena (protezione A → B → A).

    📌 Comportamento intenzionale: la funzione non solleva errori se nessun indirizzo è disponibile; restituisce semplicemente zero righe.

    🔁 Esempio di catena di fallback¶

    tipo_indirizzo fallback_tipo_indirizzo
    SEDEOP SEDELEG
    FORNITURA SEDEOP

    Effetto pratico:

    SELECT *
FROM script.fn_get_indirizzo(p_soggetto_ruolo_id, 'FORNITURA');

    Ordine dei tentativi:

    FORNITURA → SEDEOP → SEDELEG

    ⚙️ Proprietà tecniche¶

    Attributo Valore Note
    Stabilità STABLE Funzione di sola lettura su dati e configurazione
    Parallelismo PARALLEL UNSAFE Uso di geometry e logica iterativa
    Semantica Multi-row Può restituire più righe per lo stesso tipo

    🧪 Esempi d’uso¶

    -- 1) Indirizzo SEDEOP per un Gestore, con fallback su SEDELEG
SELECT *
FROM script.fn_get_indirizzo(63, 'SEDEOP');

-- 2) Uso in JOIN laterale
SELECT sr.id, sr.soggetto_id, f.indirizzo_completo
FROM anagrafiche.soggetti_ruoli sr
CROSS JOIN LATERAL script.fn_get_indirizzo(sr.id, 'FATT') AS f;

-- 3) Solo indirizzi normalizzati con geoloc
SELECT *
FROM script.fn_get_indirizzo(123, 'FORNITURA')
WHERE is_normalizzato = TRUE
  AND geoloc IS NOT NULL;

    ⚙️ Funzione fn_get_indirizzo¶

    CREATE FUNCTION fn_get_indirizzo(p_soggetto_ruolo_id bigint, p_tipo_codice character varying)

    Definizione completa:

    CREATE OR REPLACE FUNCTION script.fn_get_indirizzo(p_soggetto_ruolo_id bigint, p_tipo_codice character varying)
 RETURNS TABLE(tipo_indirizzo character varying, indirizzo_completo text, geoloc geometry, indirizzo_id bigint, soggetto_ruolo_id bigint, tipo_indirizzo_id integer, indirizzo_dettaglio_id bigint, indirizzo_libero text, is_normalizzato boolean, stato_id integer, stato_descrizione character varying, stato_iso2 character, regione_id integer, regione_descrizione character varying, provincia_id integer, provincia_sigla character varying, provincia_descrizione character varying, comune_id integer, comune_descrizione character varying, codice_postale_id integer, cap_codice character, locality character varying, administrative_area character varying, sublocality character varying, postal_box character varying)
 LANGUAGE plpgsql
 STABLE ROWS 10
AS $function$
/*
    Funzione: script.fn_get_indirizzo(p_soggetto_ruolo_id, p_tipo_codice)

    Nuova logica:
    - Prova il tipo richiesto (p_tipo_codice).
    - Se non trova indirizzi:
        * legge da config.tipi_ruolo_tipi_indirizzo il fallback_tipo_indirizzo_id
          per (tipo_ruolo del soggetto_ruolo, tipo_indirizzo corrente),
        * risale la catena di fallback finché:
            - trova almeno un indirizzo per un tipo, oppure
            - la catena termina (fallback NULL), oppure
            - rileva un loop nella catena (ciclo A→B→A).

    Per ogni tipo provato, i dati vengono recuperati da:
        script.fn_get_indirizzi_by_ruolo(p_soggetto_ruolo_id)
  Output:
  - Stesso schema di fn_get_indirizzi_by_ruolo:
    tipo_indirizzo, indirizzo_completo, geoloc,
    id tecnici, flag is_normalizzato,
    stato/regione/provincia/comune/CAP,
    campi "raw" internazionali.
*/

DECLARE
    v_tipo_ruolo_id      bigint;
    v_current_codice     text := p_tipo_codice;
    v_current_tipo_id    bigint;
    v_fallback_tipo_id   bigint;
    v_rows_found         integer;
    v_visited_tipo_ids   bigint[] := '{}'::bigint[];
BEGIN
    -- Ricavo il tipo_ruolo legato al soggetto_ruolo
    SELECT sr.tipo_ruolo_id
    INTO v_tipo_ruolo_id
    FROM anagrafiche.soggetti_ruoli sr
    WHERE sr.id = p_soggetto_ruolo_id;

    IF v_tipo_ruolo_id IS NULL THEN
        -- soggetto_ruolo non valido: nessun indirizzo
        RETURN;
    END IF;

    LOOP
        -- 1) Provo il tipo corrente (v_current_codice)
        RETURN QUERY
        SELECT
            f.tipo_indirizzo,
            f.indirizzo_completo,
            f.geoloc,
            f.indirizzo_id,
            f.soggetto_ruolo_id,
            f.tipo_indirizzo_id,
            f.indirizzo_dettaglio_id,
            f.indirizzo_libero,
            f.is_normalizzato,
            f.stato_id,
            f.stato_descrizione,
            f.stato_iso2,
            f.regione_id,
            f.regione_descrizione,
            f.provincia_id,
            f.provincia_sigla,
            f.provincia_descrizione,
            f.comune_id,
            f.comune_descrizione,
            f.codice_postale_id,
            f.cap_codice,
            f.locality,
            f.administrative_area,
            f.sublocality,
            f.postal_box
        FROM script.fn_get_indirizzi_by_ruolo(p_soggetto_ruolo_id) f
        WHERE f.tipo_indirizzo = v_current_codice;

        GET DIAGNOSTICS v_rows_found = ROW_COUNT;

        -- Se ho trovato almeno un indirizzo, ho finito
        IF v_rows_found > 0 THEN
            RETURN;
        END IF;

        -- 2) Nessun indirizzo per questo tipo: cerco fallback in matrice

        -- Ricavo id del tipo_indirizzo corrente
        SELECT ti.id
        INTO v_current_tipo_id
        FROM config.tipi_indirizzi ti
        WHERE ti.codice_interno = v_current_codice;

        IF v_current_tipo_id IS NULL THEN
            -- Tipo non riconosciuto: non posso proseguire
            RETURN;
        END IF;

        -- Protezione da loop nella catena di fallback
        IF v_current_tipo_id = ANY (v_visited_tipo_ids) THEN
            -- Rilevato ciclo A->B->A: esco senza risultati
            RETURN;
        END IF;

        v_visited_tipo_ids := array_append(v_visited_tipo_ids, v_current_tipo_id);

        -- Cerco il prossimo fallback per (tipo_ruolo, tipo_indirizzo corrente)
        SELECT m.fallback_tipo_indirizzo_id
        INTO v_fallback_tipo_id
        FROM config.tipi_ruolo_tipi_indirizzo m
        WHERE m.tipo_ruolo_id     = v_tipo_ruolo_id
          AND m.tipo_indirizzo_id = v_current_tipo_id
          AND m.attivo            = TRUE
          AND (m.valido_dal IS NULL OR m.valido_dal <= current_date)
          AND (m.valido_al  IS NULL OR m.valido_al  >= current_date)
        LIMIT 1;

        -- Nessun fallback configurato: esco senza risultati
        IF v_fallback_tipo_id IS NULL THEN
            RETURN;
        END IF;

        -- Traduco il fallback id in codice_interno per il prossimo ciclo
        SELECT ti.codice_interno
        INTO v_current_codice
        FROM config.tipi_indirizzi ti
        WHERE ti.id = v_fallback_tipo_id;

        IF v_current_codice IS NULL THEN
            -- Configurazione incoerente (id senza codice_interno): esco
            RETURN;
        END IF;

        -- Loop: riprovo con il nuovo tipo (v_current_codice)
    END LOOP;
END;
$function$
